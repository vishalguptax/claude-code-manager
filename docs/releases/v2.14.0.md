# v2.14.0

_Released 2026-09-20_

Session tabs get their identity back: renames you make in Claude Code's own UI now show up here, an unnamed session no longer opens a nameless terminal, and the terminal icon finally renders where the terminals actually open.

## ✨ Features

- **sessions: honour renames made from Claude Code's own UI** ([57a4146](https://github.com/vishalguptax/claude-code-manager/commit/57a41464073d8387e5446788e1cedd1c58f09ee6)) — Claude Code's **Rename session tab** does not write the name anywhere this extension was looking. It sends `rename_session` over its control channel and the CLI persists the result into the transcript as `{"type":"custom-title","customTitle":…}`, with a last-wins merge rule. We only read the older `/rename` command shape, the generated `ai-title`, and the auto-summary — so a session you renamed over there kept showing its stale generated title in the sidebar, the detail page, and the terminal tab. Both readers now parse `custom-title`, and it ranks directly below the extension's own rename: an explicit rename from any host outranks every generated title, while a name you set here still wins.

## 🐛 Bug Fixes

- **sessions: stop an unnamed session from opening an unnamed terminal** ([428aa5d](https://github.com/vishalguptax/claude-code-manager/commit/428aa5ddaf24a805b1542773e0bde76431d86628)) — `Session.name` is a plain string that is empty for a session no fallback ever named, and the terminal-name helper guarded it with `??`, which only catches `null`/`undefined`. The empty string went straight through to `createTerminal`, and VS Code treats an empty name as no name at all — so the tab fell back to the process name, which for the bundled CLI is the version directory it runs from (`2.1.276`). It now falls back to the short session id, the same value the list row uses.
- **terminal: show the tab icon on editor-area terminals** ([593f65b](https://github.com/vishalguptax/claude-code-manager/commit/593f65bf3632ec2507dd0381c8f5c5d95b6864d5)) — the icon was passed as a `Uri` to the bundled SVG, but `TerminalEditorInput.getIcon()` returns the terminal's icon only when it is a `ThemeIcon`. A URI icon renders in the panel's tab list and is silently dropped in the editor area — which is where these terminals open by default, so in practice the icon never appeared. It is now a codicon, which renders in both places.
