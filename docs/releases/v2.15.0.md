# v2.15.0

_Released 2026-09-20_

One new switch: keep your session names on the terminal tabs this extension opens, instead of watching a running `claude` replace them with a version number.

## ✨ Features

- **terminal: opt-in setting to keep session names on terminal tabs** ([a2c44b2](https://github.com/vishalguptax/claude-code-manager/commit/a2c44b265853b857c45d03e32d4a8fa97d7b5732)) — VS Code 1.106+ defaults `terminal.integrated.tabs.allowAgentCliTitle` to `true`, and when a terminal is running an agent CLI (`claude` is on VS Code's own list) the tab title comes from the CLI while the name an extension set is ignored outright. So a session tab lost its name the moment `claude` started: you saw the CLI's session title, or — before its first title and after it exits — the process name, which is the folder the bundled CLI runs from, a bare version number like `2.1.276`. No extension can opt a single terminal out; `titleTemplate` is a profile-only field that `vscode.TerminalOptions` does not expose, so the only lever is a global VS Code setting, which is yours to pull. Tick **Claude Code Manager › Terminal: Keep Session Names** (Settings → search "Keep Session Names") and the extension holds the two tab-title settings at the pair that works: session names on the tabs it opens, Claude Code's own title still on terminals you open yourself. Untick it and everything it displaced goes back, including a value you had set there first. It ships no `configurationDefaults` — nothing changes for anyone who leaves it off.
