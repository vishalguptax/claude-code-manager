# v2.12.1

_Released 2026-09-16_

A session with nothing new to read no longer shows as unread — the real cause was bookkeeping lines Claude Code writes to the transcript after you've closed the terminal, not the read-tracking logic itself.

## 🐛 Bug Fixes

- **sessions: stop bookkeeping lines from making a session look unread** ([d376788](https://github.com/vishalguptax/claude-code-manager/commit/d376788de9cc0e25253d57ea8cb351bf31af3fa0)) — the field unread compares against was set from the last transcript line carrying any timestamp, not the last real message. Claude Code interleaves genuine turns with plain bookkeeping lines — some written well after the terminal closes — and 63 of 78 real sessions checked had one of those inflate the timestamp. Fixed at the source, so session ordering and the "recent" filter are more accurate too, not just the unread dot.

## 📚 Documentation

- **docs: bring README and DEVELOPMENT up to date with checkpoints, prompts, plugins, memory** ([a9e9d3c](https://github.com/vishalguptax/claude-code-manager/commit/a9e9d3c720a68e5d122a614608f1acbdc1202b17)) — feature table, settings reference, and marketplace description now cover the four tabs added in 2.12.0. Also caught and fixed: DEVELOPMENT.md's "Opt-in quota fetch" section still described calling `api.anthropic.com` directly with the OAuth token — the mechanism an earlier version used, replaced for violating Anthropic's Consumer Terms. The current mechanism (a local statusline tap, zero network calls) was already correct in the README; only this doc had drifted.
