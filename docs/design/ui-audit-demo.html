What changed

  • One primary action, not six peersTemp, Restore, Import and Import Many move into the split-button menu. Six equal-weight buttons in a 135px auto-fit grid wrap to three rows at 280px and answer no question about what to click first.
  • Filters collapse to what is actually onProject, branch, worktree and date used three permanent rows. Now the bar shows only active filters as removable chips; the funnel opens the rest.
  • Row separators become a settingWhether a three-line row reads better ruled or unruled needs looking at in a real sidebar, so it shipped as claudeManager.density: comfortable keeps the rules, quiet drops them. Sticky headers were dropped entirely — VirtualList positions rows absolute, so position: sticky would be silently inert.
  • Hover overlay: left aloneAn earlier draft of this audit called the hover behaviour a defect. It is VS Code Explorer’s own pattern, and the gradient is what stops the title hard-clipping. The screen above keeps it.

What changed

  • Status reads as a labelled chipA coloured dot alone carries the live state today. The chip pairs the dot with the word, so the state survives colour blindness and a screenshot.
  • Stats become a 2×2 tile blockFour numbers in one row at 280px gave each 60px. Two columns keep the figures readable at every width.
  • Transcript gets real typographic rolesRole label, body, tool call and code block are four distinct treatments rather than four sizes of grey.

What changed

What changed

  • Connection state is on the rowA failed server is the single most useful thing this tab can tell you, and today it only appears in a banner for claude.ai connectors. Every row now carries a live / failed / disabled dot plus a retry action.
  • Four icon buttons become twoAdd stays; globe and refresh move into the overflow. Three unlabelled glyphs beside a search box is recall, not recognition.

What changed

  • Run and copy share the row-action gutterSame position, same size, same reveal as every other tab.

The audit

Read across all eight tabs, 5,929 lines of CSS and roughly ninety Preact components. The deterministic anti-pattern scan over every webview source file returned zero findings, which is genuinely rare, and the token layer in src/styles/tokens.css is better documented than most design systems that ship with a Figma file. The problems are not taste problems. They are density, hierarchy and repetition problems.

Does it look AI-generated?

No. The deterministic scan over src/webview and all eight feature webview directories returned an empty finding set: no gradient text, no side-stripe accents, no eyebrow scaffolding, no identical card grids. Every colour resolves through a --vscode-* variable with a documented fallback chain, which is the opposite of generated CSS.

The failure mode here is the product-register one instead: strangeness without purpose. Four chip shapes that are similar but not identical. The same scope concept painted green on one tab and blue on the next. Six ways to say “nothing here”. A user fluent in Linear or Raycast would not call this AI-made; they would pause at each of those seams.

What is working

  • The role-token layer. --role-primary-*, --role-selected-*, --role-ghost-* with a comment explaining why selection is deliberately not primary blue. That reasoning is worth more than the tokens.
  • Accessibility is not an afterthought. Roving tabindex on a real tablist, wrapping arrow keys, prefers-reduced-motion on every animation, a neutral badge token introduced specifically because the native badge.background pair fails contrast on light themes.
  • Loading is honest. Skeletons on first paint, an indeterminate bar after 300ms, and a deadline that swaps the shimmer for a status line and a retry. Most extensions ship a spinner and hope.

What shipped

Every issue below is now fixed on feat/sidebar-shell-redesign, in thirteen commits. Build green, typecheck clean, 2,231 tests passing (from 2,134). The screens above still show the proposal; the code is the record.

Priority issues

corrected

The tab strip had two owners, and the later one squeezed the icons

Correction
First written up as “eight labelled tabs need 680px, so half the product is off-screen”. That was wrong: components.css already hid inactive labels, so the icon rail existed. Reasoning from one stylesheet instead of the concatenated bundle is what produced the mistake.
What
The real defect was a duplicate declaration. components.css sized a tab as a 32px square with padding: 0; tabs.css loads later in build-css.js and set padding: 8px 12px with no width. Border-box arithmetic: 32 − 24 = 8px of content for a 16px glyph, so every inactive icon overflowed its own cell.
Fixed
The whole tab family now lives in tabs.css alone; components.css keeps a pointer. The active tab is scrolled into view on change, since the strip can still overflow on a hand-narrowed panel and the scrollbar is deliberately hidden.

The Sessions tab stacks an action grid of six buttons (which wraps to two or three rows under 420px), a search row, a filter row of dropdowns, a date segmented control and a count header. On a 900px-tall sidebar that is a quarter of the viewport spent before any content, every single time.
Fix
One primary split button, a search row, and a chip bar that renders only the filters that are actually set. The date range and the project, branch and worktree pickers move behind the funnel.

withdrawn

“Hovering a row destroys information”

Claim
.session-item:hover .item-time { visibility: hidden }, the same rule for .pin-icon, and an action cluster riding a gradient over the title tail. Proposed fix: a reserved 28px action gutter on every row.
Why it was wrong
This is VS Code Explorer’s own pattern — row metadata yields to actions on hover — and the gradient exists precisely so the title dissolves instead of hard-clipping. A reserved gutter would cost every row 38px permanently, over 13% of a 280px sidebar, to “fix” behaviour that is native and deliberate.
Status
Not shipping. The overlay stays as it is.
P1

A nearly flat type scale doing no work

fixed
What
10 / 11 / 12 / 13 / 14 / 16px, a ratio of 1.08 between the two most-used steps. Hierarchy therefore rests entirely on colour, and the colour ramp is --fg, --fg-dim, --fg-muted, all muted by design. Nothing on a row is emphatic.
Fix
11 / 12 / 13 / 15 / 18 with weight carrying the rest: 600 for names, 500 for body, 400 for meta. Same density, real hierarchy.

The Config tab renders .acct-section, .acct-field, .acct-label, .acct-field-hint and .acct-actions. fixed
What
.skeleton-el::after sweeps rgba(255,255,255,0.08) across a --bg-hover base. On a light theme that is white on near-white, so half the users see a static grey bar where the other half see motion.
Fix

Who this breaks for

The returning power user

Opens the sidebar twenty times a day to resume a session. Pays the 230px chrome tax every time, cannot jump to a session from the Config tab without losing their place, and has no keyboard path to Account, which is off-screen at default width. They will pin the panel wider than they want to, or stop opening it.

The first-run installer

Installed after a Google search, deciding in under a minute whether this is safe. Lands on Sessions, sees six unexplained buttons and three filter rows, and never discovers Skills, MCP or Hooks because those tabs are past the right edge of a strip with no scrollbar.

Anyone on a light theme

Gets a static skeleton instead of a shimmer, a 1px focus ring on a light ground, and low-contrast neutral chips wherever a feature still uses the old --badge-* pair rather than --badge-neutral-*.

Smaller things worth a pass

  • Descriptions truncate at 60 characters in Skills and 80 in Agents using String.slice, which cuts mid-word and ignores the real panel width. text-overflow: ellipsis already does this correctly and responsively.
  • The hook disable toggle uses the pin-off icon. It means nothing in that context; pause and play do.
  • The app footer costs about 32px on every tab for two links. Those belong in the tab-strip overflow.
  • Five features hard-code a virtualization threshold of 50 and a fixed row height (64, 84, 48, 56, 56) that has to be kept in sync with CSS by hand. One measured-row virtual list would remove five sources of drift.
  • Group-header rows in Sessions are collapsible; the same headers in Skills, Commands, MCP, Agents and Hooks are not. Same visual, different behaviour.

Questions worth answering before building

  • Do Commands and Skills need to be separate tabs? Both are /name invocations backed by a markdown file, and merging them would take the strip to seven.
  • If the palette lands, does the per-tab search box still earn its 36px?
  • What does this look like at 220px, which is where a developer with a split editor actually leaves the sidebar?
