Where MCP servers come from

Every MCP server Claude Code loads, and where it's defined

A server can be defined in more places than most people check. The MCP tab reads all of them and labels each server with its source.

  1. .mcp.jsonProject serversIn the project's .mcp.json — and in any .mcp.json in a parent folder, which is easy to forget.
  2. ~/.claude.jsonUser and local serversServers added for every project, or only for one, live in ~/.claude.json.
  3. plugins/*/.mcp.jsonPlugin serversPlugins can bring their own servers.
  4. ~/.claude/mcp.jsonThe legacy file, flaggedServers left in the old ~/.claude/mcp.json are shown with a note: Claude Code no longer reads that file, so they never load until you move them.

Enable, disable, add and fix servers

  1. on / offSwitch a server off without losing itFlip a switch; the configuration stays. Project servers are toggled in .claude/settings.local.json, others in ~/.claude.json.
  2. formAdd or edit without JSONFill in a form, or pick from a catalog of 16 common servers that ships inside the extension.
  3. needs authSee which servers need you to sign inA banner lists servers Claude Code has marked as needing re-authentication; sign in runs claude mcp login in a terminal.
  4. ****Secrets stay hiddenAPI keys and tokens in a server's settings are masked in the list.
  5. claude mcp listCheck with Claude Code itselfOne click runs claude mcp list in a terminal, so you can see what the CLI sees.
